How the transfer survives dropped frames

Each QR contains the XOR of a deterministic pseudorandom subset of source blocks. The receiver reconstructs the file from any sufficient collection of distinct frames; it does not need every frame or a back-channel.

Built-in local HTTPS hosting

A normal web page cannot open a server port by itself. This page carries self-contained launcher generators that create a temporary HTTPS server outside the browser and serve an embedded copy of this exact app.

Choose the launcher for the computer that will host the page.
Windows: download the generated .cmd, double-click it, allow Private network access if Windows Firewall asks, and keep its window open.
macOS/Linux: download the generated .command, run chmod +x on it if required, then open it in Terminal.
Connect the receiving phone

The launcher prints an address such as https://192.168.1.25:8443/. Open that exact address on the phone, accept the certificate warning only on a private network you trust, select Receive, and allow camera access.

Why a launcher is required

Browser JavaScript is intentionally sandboxed and cannot bind a TCP port, install a certificate, or become an HTTP server. The launcher performs those operating-system tasks. The app itself remains contained in this HTML and is copied into the launcher when you press the button.

HTTPS host included

The generated launcher contains the current HTML as Base64, creates a temporary self-signed certificate, serves the page on port 8443, and removes its temporary certificate or files when stopped.
No Node.js, npm, Vite, Python, or separate web folder is required on Windows. The macOS/Linux launcher uses built-in Python 3 and OpenSSL.
